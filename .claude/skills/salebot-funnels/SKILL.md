# Воронки Рыжикова в Salebot

Ты пишешь воронки для Пети Рыжикова: ниша РКО, банковские партнёрки, ИП на НПД, обучение (Ryzhikov Academy).
Цель любой воронки: довести человека из контента до **живого диалога** и **созвона-диагностики** у МОПа.
Дальше лид живёт в CRM команды (`team/` в этом репозитории): лид → ЛМ → созвон → отчёт → решение → оплата.

## 1. Канон (не менять без Пети)

Все тексты используют ровно эти факты. Расхождение между ботом, каналом и YouTube убивает доверие.

- **2 года назад** работал в вейпшопе за **50–70к**, висел долг **90к**, сливал деньги на ставках.
- Пришёл в РКО и банковские партнёрки, в марте сделал **1 000 000 ₽**.
- **200+ учеников**.
- Кейсы (имена и цифры дословно):
  - **Гоша**: без денег, до этого P2P без капитала, блокировки по 115-ФЗ. Через 3 месяца 450к, купил машину.
  - **Кирилл**: работал в магазине у брата. На второй месяц ~500к, Ford Focus на третий месяц.
  - **Слава**: Ишимбай, до этого «темки». На второй месяц 200–250к, теперь куратор.
  - **Дима**: полгода назад в −40° бурил стены, спал по 2–3 часа. Сейчас 250–450к в месяц.
  - **Ромчик**: 300к кассы за 10 дней.
- Лид-магнит: видео «как выйти на 300к за 3 месяца на РКО». Называть **«видео»/«видос»**, не «урок».
- Механика входа: самозанятость в «Мой налог» → ИП на НПД через Альфу (до 15 000 ₽) → РКО и другие офферы → один человек проводится через несколько банков (30–60к, до 130к с человека).

Если нужен новый факт или кейс, спроси Петю, а не придумывай.

## 2. Голос

- На «ты» везде, включая ответы в комментариях. Никаких «Ловите», «Откройте», «Приветствую».
- «Умный спокойный хищник»: уверенно, прямо, с цифрами, с лёгким стёбом над бедным мышлением. Без унижения читателя.
- Нельзя: «детка», «не тупи», «большое количество ребят», «отличные результаты», канцелярит, мотивация без цифры.
- Каждое сообщение — одна мысль и одна кнопка. Первое сообщение после входа в бота — не длиннее 4–5 строк.
- Конкретика бьёт общее: «Ромчик, 300к за 10 дней» вместо «ребята делают результаты».
- Дефицит только честный: «беру ограниченно, диагносты не резиновые». Не «осталось 3 места» в каждой ветке.
- Обещал «последнее напоминание» — дальше не пишешь. Обещал «напиши СТОП» — блок СТОП обязан существовать.
- После черновика прогоняй текст через скилл `humanizer-ru`.

## 3. Скелет воронки

```
Инста: коммент с кодовым словом
  → лайк + ответ в комментах (select_random из 3–4 фраз на «ты»)
  → директ: короткий текст + кейс + ссылка t.me/<bot>?start=<источник>
TG-бот /start <источник>
  → запись лида в таблицу/CRM (источник, время, id)
  → 4 строки + [ПОДПИСАТЬСЯ] + [ПРОВЕРИТЬ ПОДПИСКУ]
  ├─ не подписан: «не вижу» → 15 мин → 24 ч (последнее) → конец
  └─ подписан: история + [ЗАБРАТЬ ВИДЕО] (t.me/m/... в личку) → уведомление менеджеру
       нет клика: 15 мин → 24 ч (боль + кейсы) → 48 ч (бесплатный разбор)
                  → 60 ч (польза без просьбы, МФО-статья) → 96 ч (финал + СТОП)
       клик на любом шаге: уведомление менеджеру с названием шага, дальше живой диалог
СТОП: на любом шаге «стоп» → снять с цепочки, ответить, больше не писать
```

Правила ветвления:
- Ветки «нажал» и «не нажал» не сходятся: текст «раз ты забрал видео» получает только тот, у кого был клик.
- Каждая ссылка — кнопкой через `proxy(...)`, чтобы ловить `link_was_pressed`. Голая ссылка в тексте не отслеживается.
- Для каждого источника (inst, yt, reels, трафик) свой `start=` и своя метка, чтобы считать конверсию.

## 4. Справка по Salebot (то, что уже используется в проекте)

Переменные: `#{name}`, `#{full_name}`, `#{tg_username}`, `#{client_id}`, `#{platform_id}`, `#{tag}`, `#{current_date}`, `#{current_time}`.

Калькулятор:
```
# проверка подписки (бот должен быть админом канала)
result = tg_get_chat_member('<id канала>', platform_id)
res = get(result, 'result')
member_status = get(res, 'status')
# подписан: member_status != 'left' and member_status != 'kicked'

# ссылка-кнопка с отслеживанием клика
linkvideo = proxy("https://t.me/m/<код>")

# уведомление менеджеру
text = "🔥 #{full_name} @#{tg_username} id #{client_id} | шаг: ВИДЕО | ответь сейчас"
tg_send_message(<id чата менеджеров>, text)

# запись в Google-таблицу (пробел между датой и временем!)
store_result = {}
store_result["a"] = "#{current_date} #{current_time}"
store_result["b"] = "#{full_name}"
store_result["c"] = "#{tg_username}"
store_result["d"] = "#{client_id}"
store_result["e"] = "#{tag}"
store_result = sheet_mapping_cells("<id таблицы>", store_result, "Клиенты")

# Инста
like_client_message()
textcomment = select_random('#{t1}|#{t2}|#{t3}')
insta_create_comment('#{textcomment}')
```

События и условия: `link_was_pressed` (клик по proxy-ссылке), `client_wall_reply_new_comment` (коммент в Инсте), стартовые условия `inst;/start` на полном совпадении.

Что проверить в документации Salebot или тестом на себе перед тем, как на это полагаться:
- отменяется ли отложенный переход «Через N», если клиент ушёл в другой блок;
- как снять клиента со всех таймеров для СТОПа (переменная-флаг + условие на переходах или отдельный блок без выходов);
- окно отправки, чтобы дожимы не уходили ночью.

Id каналов, таблиц и чатов в этот файл не писать: репозиторий публичный.

## 5. Чек-лист перед запуском

1. Цифры и история совпадают с разделом «Канон».
2. Везде «ты», нет «детка», «не тупи», канцелярита.
3. Стартовые условия на точном совпадении, без мусорных слов вроде `вапукпкп`.
4. Ветки нажал и не нажал не пересекаются, нет висящих блоков без связей.
5. Все ссылки — кнопки через proxy, на каждую стоит `link_was_pressed` → уведомление с названием шага.
6. Есть блок СТОП, «последнее напоминание» действительно последнее.
7. Если канал с заявками на вступление, проверка подписки ломается (до одобрения статус `left`). Нужно автоодобрение или проверка по заявке.
8. В таблицу или CRM пишутся источник и время с пробелом, повторный /start не плодит дубли.
9. Прогнать воронку на своём аккаунте: подписан, не подписан, нажал, не нажал, СТОП.
